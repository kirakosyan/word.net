# Bucket 5 fixture provenance and acceptance plan

Design-time test specifications for #28–#31, authored 2026-10-17 under the repository
MIT license. These are **planned cases**, not enabled/skipped tests, generated binary
fixtures or evidence of runtime support. Follow [the decision index](../later-design-decisions.md)
for the original stage boundaries. At that design checkpoint the required runtime
suite had 829 cases; [testing](../testing.md) records later build-specific evidence.

## Provenance and independent tooling

All proposed documents use synthetic text/data: `Review Author A/B`, fixed UTC dates,
`Invoice 42`, values `[10, 20, -5]`, categories `Alpha/Beta/Gamma`, and equations such
as `(x + 1) / 2`. Password fixtures use the public test-only phrase
`wordnet-fixture-only-42`; this is intentionally public and is never a credential or
a suggested production password. Do not use customer documents, live URLs, personal
metadata or proprietary code/resources. Hostile relationship tests use reserved
`example.invalid` and sentinel local paths that must never be opened.

Existing independently authored MIT seeds:

- `tests/wordnet.Conversion.Tests/Fixtures/Comparison/contract-revisions.docx`,
  generated by `eng/generate-comparison-corpus.py`; current accepted-state/review-loss
  controls. Its actual hash and expected diagnostics are in the comparison manifest.
- The other eleven [comparison documents](../../tests/wordnet.Conversion.Tests/Fixtures/Comparison/README.md)
  supply supported tables, lists, stories, page layouts and rasters for ODT mapping.
  They are semantic inputs, not ODT/review/object qualification.
- [Fixture policy and independent inputs](../../tests/wordnet.Conversion.Tests/Fixtures/README.md)
  retain their own licenses/hashes. Do not repurpose third-party fixture content unless
  its recorded license covers the new use.

Future generators must be standalone Python ZIP/XML/specification writers under MIT,
not call wordnet serializers. Store generators, deterministic package seeds and
machine-readable manifests with source/version, license, SHA-256, semantic expectations,
feature losses, expected stage, fonts, tool/runtime and exact invocation. Random encrypted
outputs are intentionally nondeterministic: hash the retained exact files and record
the generation command, never add a fixed production RNG to make hashes reproducible.
Malformed variants identify the seed and exact mutation. Review generated XML/data
against specifications and an external reader before they become positive test oracles.

| Tool | Independent use / deployment decision |
| --- | --- |
| OASIS ODF 1.3 schemas with a pinned Relax NG validator | Validate package XML plus separate ZIP/manifest rules. Record schema/validator hashes and their notices before checking in downloaded assets; linked specifications alone are not MIT artifacts. |
| Open XML SDK (existing test dependency) | Validate supported DOCX/chart/OMML/XLSX outputs; separately inspect semantics/ranges/data. No production dependency. |
| LibreOffice | Separate installed command-line reader for ODT/DOCX conversion and pinned PDF renderings; GUI editing control for chart/equation. Record exact version/platform/fonts. External tool only; do not bundle externally licensed binaries or copy implementation code. |
| msoffcrypto-tool (MIT) and Apache POI (Apache-2.0) | Independently encrypt/decrypt synthetic Agile files and compare complete ZIP payload hashes; choose pinned versions supporting the exact AES/SHA profile. Production never invokes Python/Java. Retain licenses for any redistributed tool-derived fixture. |
| MuPDF/Poppler plus font inspection | Independent glyph/geometry/pixel measurement, with tool/font versions and licenses recorded. Optional tools are development prerequisites, not new runtime dependencies. |
| Caller-provisioned Microsoft Word | Optional second office reader and authoring/edit control, with product/build recorded. No automation/license key is committed and absence is reported explicitly. LibreOffice results cannot be described as Word qualification. |

Tool licenses apply to tools; synthetic documents authored by this project have their
own MIT provenance. Before redistribution inspect exported metadata and embedded fonts
for third-party assets; choose repository OFL faces or a separately reviewed OFL math
face. Do not infer that a tool's license automatically licenses arbitrary sample files.

## ODT plan (#28)

| ID | Fixture / assertion |
| --- | --- |
| O-01 | Standalone ODF 1.3 text package with Unicode, repeated spaces/tab/newline, default/named/automatic styles and title/author. Independent reader must recover exact text/order and expected resolved size/color/emphasis. |
| O-02 | Parent-style chain, missing parent and cycle; supported chain resolves identically on all TFMs; invalid chain fails before destination copy. Different style identities with identical supported appearance produce an explicit identity-loss report. |
| O-03 | Nine-level list with zero/positive starts, Roman/letter labels and restarts; inspect actual numbering definitions and external reader labels, not flattened label text alone. |
| O-04 | Two master pages with different physical sizes/margins and simple stories; inspect DOCX sections and reader page geometry. Unsupported continuous/nested rules produce the specified loss. |
| O-05 | Table widths, spans, covered cells, repeated rows/columns, color/padding, inline PNG/JPEG and alt; independently inspect merge rectangles, image SHA-256 and 60 × 30 pt frame. Invalid spans fail in all modes. |
| O-06 | Duplicate/unsafe/encoded paths, external links, missing/duplicate manifest entries, compressed/wrong/misplaced mimetype, DTD, encrypted/signature/script/OLE declarations and actual expansion beyond declared budget; assert no filesystem/network access and unchanged sentinel output. |
| O-07 | Independent LibreOffice-authored ODT from synthetic source, and standalone authored DOCX → wordnet ODT → independent reader. Validate both destination schemas, two advertised pairs and rejected other pairs. Round trips supplement, never replace, cross-reader assertions. |
| O-08 | Large repetition products/style chains, maximum limits ±1 and cancellation mid-expansion. Fail before allocations exceed admitted structure; preserve stream positions/ownership and destination safety contracts. |

Pinned renderings compare text/order and table/image geometry within 0.5 pt for simple
frames; compare ink masks only for the same pinned font/renderer. No arbitrary page-count
parity or exact Word pagination requirement. Establish baseline thresholds using an
independent authored reference, then lock them before accepting a production change.

## Review history plan (#29)

| Stage | Independent fixtures and required assertions |
| --- | --- |
| R1 preservation | Body/cell insertions and deletions with distinct authors, absent/present dates, point/range comments and crossing comment intervals. Count actual revision/comment parts/markers, match full deleted/current text and metadata, schema-check, then enumerate in an external reader. Save without edits retains semantics; clone/append remaps every ID. |
| R1 rejection controls | Move-from/to pairs, run/paragraph format history, deleted paragraph marks, table row/cell revisions, field/TOC/control boundaries, headers/footers/notes and modern threaded comments. Valid unsupported cases reject preserve-mode loading; malformed duplicate/orphan/cross-story markers fail as invalid data. Existing default permissive/Strict behavior is separately asserted unchanged. |
| R2 decisions | On supported insert/delete fixtures accept-all equals independently authored accepted document; reject-all equals independently authored original. Mixed selections and comments intersecting removed ranges exercise atomic failure; comment removal must be explicit. R2b format tests inspect prior and current properties separately. |
| R3 recording | Replace `Total 10` with `Total 20` in a supported paragraph; inspect real insertion/deletion author/date/markup and accepted/rejected views. Invalid/stale handles or unsupported field/story edits leave session and diagnostics unchanged. |
| R4 comparison | Revision/comment-free matched paragraphs/cells with word/punctuation/whitespace changes, emoji/combining clusters, repeated ambiguous tokens and RTL logical text. Apply/accept generated changes recovers revised semantics; reject recovers original semantics. Record deterministic edit script and supported formatting, without asserting Word's proprietary diff choices. |
| R4 rejection/limits | Existing history in either input, added paragraph/table topology, non-text differences, too many tokens/steps and cancellation. Fail without changing either input, with no unbounded fallback or implicit history acceptance. |
| Privacy/ranges | Search serialized output after explicit sanitization for removed author/comment/deleted-text values; inspect ZIP parts, not rendered text alone. Logs/exceptions must not contain values. Include missing dates, crossing anchors, invalid UTF-16, grapheme boundaries, ID collisions, handle invalidation and aggregate deleted-content budgets. |

## Encryption plan (#30)

| ID | Independent fixture / acceptance |
| --- | --- |
| E-01 | Independently encrypt synthetic DOCX with the exact Agile AES-256-CBC/SHA-512 profile. Correct public fixture password recovers the complete original ZIP byte hash; independently decrypt wordnet output to the same bytes. A self round trip alone cannot pass. |
| E-02 | Missing, empty, wrong, non-ASCII, supplementary-character, ill-formed and oversized passwords. Preserve explicit empty-password semantics; never normalize. All failures leave sentinel unchanged, streams open and attempted values absent from errors/logs. |
| E-03 | Supported descriptor boundaries; unsupported version/cipher/hash/key length/chaining/encryptor, missing integrity, invalid XML/base64, corrupt salts/lengths and duplicate streams. Reject before expensive work or plaintext parsing as appropriate. |
| E-04 | Spin counts 99,999 / 100,000 / 1,000,000 / 1,000,001, aggregate derivation budget ±1, cancellation during KDF, decrypt and HMAC. Instrument work in test-only observers; no public password probe or production RNG hook. |
| E-05 | Truncated CFB/sector cycles/overlaps, corrupt first/middle/final cipher segments, wrong length prefix and invalid HMAC/verifier. No unauthenticated plaintext reaches ZIP parser or caller output. Wrong password and authentication corruption share a content-free category. |
| E-06 | Authenticated encrypted ZIP bomb/unsafe paths, macros, non-DOCX, restrictions/signatures and nested oversized data. Authentication success never bypasses format/resource preflight. |
| E-07 | Repeated encryption of identical plaintext/password differs; external reader opens both. Check admitted salt/key field lengths, complete HMAC verification and independent data consistency; no claim that a small sample proves RNG quality. |
| E-08 | Cancellation before final copy, throwing/truncated destination stream, same-stream aliases and nonzero input/output positions. Stage/validate failures leave destination unchanged; final-copy failures may be partial and are reported honestly. Review buffer cleanup on each failure path without claiming guaranteed managed-memory erasure. |

Actual native/Framework provider execution and an expert cryptographic review are
release gates. Do not record a security certification or minimum-Framework claim from
compilation, independent decryption alone or tests on a newer installed Framework.

## Chart/equation plan (#31)

| Stage | Independent fixtures and required assertions |
| --- | --- |
| P1 preservation | Standalone authored DOCX with a clustered-column chart, line chart, consistent one-sheet XLSX/caches and OMML fraction/root/sub/sup. SDK-check all parts; compare graph closure, references, IDs, finite values, expression tree and unchanged binary hashes after save/append. |
| P1 rejection | Every excluded chart/math construct, external chart/workbook relations, ZIP traversal/cycles, VBA/OLE/ActiveX, signed content, hidden/extra sheets, formulas, cache/workbook disagreement and absent previews. Strict fails losses; permissive available fallbacks report both semantic and visual limitations as applicable. Never fetch an external target. |
| P2 visuals | Independently positioned simple chart reference with known category/axis/value mapping and negative/zero values; measure tick/series geometry within 0.5 pt and exact labels. Compare fraction baseline, numerator/denominator, scripts and root bar against a pinned independent renderer/math font, with baseline tolerances locked before implementation acceptance. Review visual outputs and record honest font/layout differences. |
| P3 chart editing | Edit one public series value and category; inspect new chart caches and actual embedded worksheet cells for agreement. Open chart-data editor in external LibreOffice/Word, change another value, save/reopen and verify updated values/plot. An image/thumbnail-only document fails. |
| P3 equation editing | Edit denominator through the proposed expression API, then through an external equation editor; save/reopen, inspect real `m:f/m:den` content, fraction structure and visual change. Plain text/image replacement fails. |
| Lifecycle/limits | Shared resources across two charts, ID/part collisions during composition, range deletion, template repeats/conditions, clone independence, stale handles, cancellation and node/byte/series/cell/point budgets ±1. Reject unsupported edits atomically and never leave dangling parts. |
| Accessibility | Validate object descriptions/reading order and genuine semantic representation before permitting UA. Negative missing-description and unqualified math tests must fail; a valid ordinary PDF does not qualify UA. |

External editing checks are required and manual where no independent automation can
exercise the editor. Retain screenshots/structural before-after evidence and actual
tool versions. An unexecuted manual plan is never a completed editability claim.

## Promotion and documentation gates

For each future implementation slice: record exact source/head SHA, fixture/tool/font
hashes, complete test counts (no required skips), failures, explicit remaining losses,
source vs packed mode and actual OS/architecture/runtime. Run AGENTS locked restore,
all-target Release build, full applicable conversion/OCR suites, format and package/API
validation. Exercise explicit Standard assets and actual supported native lanes;
preserve current 36 directions and ownership/cancellation/fidelity behavior.

Update README, implementation plan, architecture, fidelity/API/usage/diagnostic catalog,
provider/dependency notices, executable samples and build-specific testing evidence.
After merge reconcile each acceptance criterion and roadmap #32; close only the
bounded delivered issue. None of this design plan qualifies runtime features, publishes
a package, installs new runtime dependencies or creates a release commitment.
