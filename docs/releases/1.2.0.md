# 1.2.0 — business-document automation and interoperability

Release profile for Windows/Linux x64 and ARM64. `wordnet`, `wordnet.Fonts` and
optional `wordnet.Ocr` share version **1.2.0**. This minor release adds compatible
APIs and bounded capabilities after 1.1.0; AssemblyVersion remains 1.0.0.0.

Publication and exact-artifact qualification are recorded in
[release readiness](../release-1.2.0-readiness.md). A merged version change or a
passing PR is not evidence that NuGet publication has completed.

## New capabilities

- Business-document layout: nested/decorated tables, percentage widths and bounded
  autofit; anchored/transformed PNG/JPEG and rectangular text boxes; continuous/parity
  sections, equal-width columns and page labels; multilevel lists, page-bottom notes
  and bounded TOC/bookmark/sequence refresh. See the [fidelity profile](../document-fidelity.md).
- `WordDocument` creation/editing, formatting-preserving text and bookmark replacement,
  append/composition with identifier isolation, scalar mail merge, repeating rows,
  conditions and caller-provided image placeholders. See [automation usage](../editing-and-templates.md).
- Safe HTML/CSS input and bidirectional RTF exchanges with Word, extending the
  converter matrix to **36 directed exchanges**. All resource resolution remains
  offline and explicit. RTF uses the declared CodePages 10.0.12 dependency, including
  the .NET Standard fallback on .NET 8. See [interoperability](../interoperability.md).
- Opt-in Arabic/Latin typography through matching `wordnet.Ocr` HarfBuzz assets;
  semantic tagged PDF and a bounded, independently validated PDF/UA-1 profile;
  selected physical-page export and SVG/PNG previews. PNG requires the optional
  native provider; managed Latin PDF/HTML/SVG remains available without it.
- Opt-in digital PDF reconstruction and OCR word/region confidence, source coordinates
  and editable-text spans. English printed OCR remains the supported language profile.
- Bounded preflight, location-aware diagnostic occurrences and an independently
  authored business comparison corpus. Optional commercial references are caller
  provisioned; the project does not claim arbitrary Word/Aspose parity.

PR #38 also fixes native shaping font storage: HarfBuzz owns a stable copy rather
than retaining a pointer to an unpinned temporary managed array. A compacting-GC and
allocation-pressure regression verifies independent Arabic glyph/cluster/advance/
mark-offset expectations. The required suite is **829 cases**.

## Upgrade and deployment

Update all explicitly referenced packages together:

```sh
dotnet add package wordnet --version 1.2.0
# Add for PDF input/OCR, native typography or PNG previews:
dotnet add package wordnet.Ocr --version 1.2.0
```

These commands require the version to be listed on NuGet; before publication,
use the candidate project references or the verified local package source.
`wordnet.Fonts` is restored by core. Existing converter signatures, enum values and
the four-argument `TemplateImage` constructor remain. New settings are opt-ins;
ordinary managed Latin PDF and OCR text defaults remain. Review returned diagnostics,
especially when switching an earlier workflow to Strict.

Core and OCR targets remain `net462;net472;netstandard2.0;net8.0;net10.0`;
the managed font resource package retains its `netstandard2.0` asset. Supported desktop
platforms remain Windows/Linux x64 and ARM64, with architecture-matched native
providers and explicit English OCR prerequisites. Actual Framework 4.7.2 x64 requires
legacy JIT and fresh source/exact-package qualification for this release. Actual
4.6.2, Android, macOS and trimming/AOT are not qualified by compile metadata or older
release reports. No target or minimum-runtime gate is silently removed.

## Bounded support and deferred work

These additions implement the linked supported profiles, not complete Word pagination,
arbitrary scripts/drawings/CSS/fields, general PDF layout recovery or universal
accessibility. Native typography and PDF/UA remain separate profiles; unsupported
combinations and complex semantic tables are explicit. Pinned veraPDF and independent
reader evidence do not constitute an arbitrary-document accessibility guarantee.

Bucket 5's ODT, review-history/comparison, DOCX encryption and chart/equation ADRs are
**design deliverables only**. No ODT converter, revision editor/comparator, password
utility or editable chart/equation API is shipped in 1.2.0. Current unsupported-feature
diagnostics and Strict staging guarantees remain. See [later designs](../later-design-decisions.md).

Input/expansion/text/node/page/pixel limits and cancellation are admission controls;
hard CPU/RSS/deadline enforcement requires host isolation. Streams remain caller owned.
Validation/loss failures before final copy leave output untouched; final I/O or
cancellation during copying can leave partial bytes.

## Qualification

The source and package suite requires 829 cases without failures/skips, native
Windows/Linux x64/ARM64 runs, modern and explicit Standard fallback checks, API
compatibility against 1.1.0, dependency/license/archive checks, independent format/
typography/UA/PDF-A evidence and resource/performance campaigns. Publication additionally
requires successful exact-main CI and fresh actual-4.7.2 source and immutable-package
reports with release key/JIT/hash evidence. The [readiness ledger](../release-1.2.0-readiness.md)
records current results and missing gates; historical results are preserved in [testing](../testing.md).
