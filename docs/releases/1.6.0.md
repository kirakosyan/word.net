# 1.6.0 — bounded compatibility and document workflows

`wordnet`, `wordnet.Fonts` and `wordnet.Ocr` use the same version. This release
packages a bounded milestone from [roadmap #138](https://github.com/kirakosyan/word.net/issues/138);
the roadmap and its remaining acceptance work stay open. The [source matrix](../roadmap-138-source-matrix.json)
lists tested and rejected combinations. These profiles do not imply unrestricted
Microsoft Word fidelity or support for every combination of features.

## Changes

- Resolve selected local DOCX theme text appearances and retain bounded table
  styles, borders and shading, with explicit diagnostics for unqualified cases.
- Preserve selected glossary metadata; extend bounded typed-control ownership,
  creation and removal; and compose admitted fields, controls, charts and equations
  into body or simple-cell destinations.
- Add a detached PDF/SVG review display for selected text revisions and numbered
  annotations, plus bounded comparison policies for story text and formatting.
- Extend mixed report nesting and cross-tab placement and refresh a conservative
  subset of numeric table formulas and percentage pictures.
- Add selected chart forms, point labels, basic vector shapes, cardinal gradients,
  general-angle text boxes and matrix/n-ary equation authoring. Independent
  reference differences remain diagnosed in the affected static-output profiles.
- Add bounded caller-supplied hyphenation, Japanese/Chinese line-breaking options,
  selected native-typography combinations and opt-in managed accessibility and
  tagged archival profiles.
- Recognize macro-free DOTX/OTT identities and inspect bounded format signatures;
  add a bounded immutable preview-layout snapshot.
- Inspect declared template data and selected fields and compile a narrow,
  in-process plain-DOCX-to-PDF policy plan. General template execution, portable
  plans and complete loss-policy enforcement are not included.

The linked [implementation status](../implementation-plan.md) and feature profiles
define the admitted owners, output types, resource rules, diagnostics and remaining
work for each item. Some features require explicit non-strict or opt-in settings.
The retained [1.5.0 baseline](../fidelity-138-initial.md) is historical evidence,
not a new parity claim.

## Compatibility and limits

The core and OCR packages retain `net462;net472;netstandard2.0;net8.0;net10.0`;
`wordnet.Fonts` targets `netstandard2.0`. AssemblyVersion remains 1.0.0.0. API
compatibility is checked against 1.5.0 during packing. Layout and rendering fixes
can change pagination; verify representative templates and diagnostics when upgrading.
PDF input requires the matching optional OCR provider, and English OCR needs local
Tesseract and language data.

Actual Framework 4.7.2 x64 requires the documented legacy-JIT configuration.
Actual Framework 4.6.2, Android/macOS release support, extra OCR languages,
encryption and signatures remain outside the release profile. Native typography,
review, accessible/archival output and drawings have separately bounded profiles;
support for one does not imply support for every combination. Final-copy I/O or
cancellation can leave a partially written caller stream. Independent Word/Aspose
references were not provisioned for the documented open-reference comparisons.

## Qualification and publication

The release requires successful exact-main desktop source and package/Standard
checks, actual Framework 4.7.2 source and immutable-package guests, independent
validators, performance/resource checks and package inspection. The publishing
workflow retests the same artifact before uploading. These are gates to be verified
for the final release commit; this document alone does not establish publication.
Historical measurements retain their original source, package and runtime identities.
