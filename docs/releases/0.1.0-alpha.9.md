# wordnet 0.1.0-alpha.9

First public **evaluation alpha** of the independent MIT-licensed .NET Word converter.
The package and assembly are `wordnet`; the public C# namespace is `WordNet`.

## Included

- All 28 directions: DOC ↔ DOCX; each Word format ↔ PDF, Markdown, TXT, EPUB, MOBI
  and AZW3; each Word format → XPS.
- Local English printed-text OCR for scanned/mixed PDF → editable DOC/DOCX. The host
  supplies Tesseract 5 native libraries and English data; these are not in the NuGet.
- Supported font sizes/colors, alignment, simple tables with widths/padding, editable
  decimal/bulleted lists and inline PNG/JPEG in the documented format profiles.
- Explicit diagnostics for detected fidelity losses, bounded input/output, caller-owned
  streams, synchronous and asynchronous APIs.
- `net472`, `netstandard2.0`, `net8.0` and `net10.0` assets with matching public APIs.

## Evidence and limits

The 236-case suite includes every conversion direction, OCR, independent DOCX validation,
formatting/image regressions and malformed-input checks. It passes on native Windows and
Linux x64/ARM64 CI runtimes, Windows Framework, and a Samsung ARM64 Android 16 device.
Release publishing additionally runs the suite against the exact CI-built NuGet on the
desktop runtime matrix. Android device evidence applies to the unchanged converter source;
the hosted Android job is compilation-only.

This is **not production-qualified**. Word pagination, sections, headers/footers, merged
tables, complex typography, broad EPUB/Kindle compatibility and noisy/complex OCR remain
limited. Password protection, tracked changes/comments and editable charts/equations
are deferred. Resource admission checks are not a CPU/memory sandbox. Broader independent
corpora, fuzzing, measured performance and minimum OS/device coverage are still needed.
macOS is deferred; trimming/AOT are not qualified.
