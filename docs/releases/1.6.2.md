# 1.6.2 — import content preservation and bounded parsing

`wordnet`, `wordnet.Fonts` and `wordnet.Ocr` advance together to 1.6.2. This patch
addresses [issues #183–#188](https://github.com/kirakosyan/word.net/pull/189).

## Fixes

- Preserve HTML and shared ebook list items and block order through block quotes,
  wrapper elements, definition lists and table cells.
- Retain DOCX non-breaking and soft hyphens and equivalent binary DOC controls.
  Font-specific DOCX symbols become visible U+FFFD replacements; positional tabs
  become ordinary tabs. Both approximations have explicit fidelity diagnostics.
- Decode Markdown named, decimal and hexadecimal character references while
  retaining surrounding emphasis and links.
- Accept inert HTML/XHTML DOCTYPE declarations in EPUB chapters and predefined
  HTML named characters. DTDs are ignored with a null resolver; custom entity
  references and malformed chapters reject with part-specific errors. Package
  metadata and OOXML XML restrictions remain unchanged.
- Check HTML ancestry and cancellation during tree construction, including the
  shared EPUB/MOBI/KF8 reader, before deeply nested input expands parser state.
- Bound Markdown inline-link lookahead, including failed attempts that fall back
  to reference links, and observe cancellation during link parsing.

## Compatibility and limits

The public API, dependency versions and five library targets are unchanged.
Strict mode rejects the diagnosed symbol and positional-tab approximations.
The Markdown work allowance is `max(4096, 64 × input characters)`; failed lookahead
charges the remaining inline block. Long blocks with many malformed link attempts
can reject with `Limit.MarkdownWork` in every fidelity mode. HTML ancestry uses
the configured nesting limit. These cooperative checks do not replace a worker
deadline or hard process limits. See [hosting guidance](../hosting.md) and
[diagnostics](../diagnostics.md).

The [1.6.0 feature profiles](1.6.0.md) and [1.6.1 import admission limits](1.6.1.md)
remain in effect. Windows/Linux x64/ARM64 are the desktop scope; actual Framework
4.7.2 x64 requires the documented legacy JIT. Actual Framework 4.6.2, Android/macOS,
additional OCR languages, encryption and signatures remain unqualified or deferred.

## Qualification and publication

The release requires exact-main source and immutable-package CI, all **2,550**
conversion/OCR cases without failures or skips, independent validators, performance
and resource checks, and fresh actual Framework 4.7.2 source/package evidence with
verified cleanup. The 39 new regression cases cover content order, exact characters,
fidelity modes, chapter validation, unchanged destinations and parser cancellation.
Cancellation controls retain their five-second regression ceilings. Comparison-tool
downloads have bounded retries and a checksum-verified Maven Central mirror;
twelve offline controls cover retry, fallback and corrupted-archive behavior.

The publishing workflow retests the same immutable CI packages before Trusted
Publishing. The GitHub release records the tested final commit, CI/publication runs,
package hashes, public-package verification and minimum-runtime evidence. This
source document alone does not establish that publication has completed.
