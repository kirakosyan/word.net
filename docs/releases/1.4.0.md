# 1.4.0 — report integration and document layout

`wordnet`, `wordnet.Fonts` and `wordnet.Ocr` advance together to 1.4.0. This minor
release extends the bounded 1.3.0 profile through roadmap #99 issues #87–#98.
Use matching package versions. Publication is separate from merging these notes;
the [release page](https://github.com/kirakosyan/word.net/releases/tag/v1.4.0) records
the qualified commit, CI/publication runs and immutable package evidence when released.

## Additions

- Direct HTML-to-PDF and ODT-to-PDF conversion through the existing bounded readers
  and shared layout engine. The conversion matrix has 40 enabled directions.
- Immutable `ChartDataBinding` projects report categories, series names and finite
  nullable values into supported charts, updating chart caches and the actual workbook
  atomically. Controlled/repeated chart owners remain unsupported.
- Bounded `DOCPROPERTY`, `IF` and decimal arithmetic fields. Unsupported grammar,
  nested instructions, missing properties and arithmetic errors retain source caches
  with informational diagnostics, including in Strict mode. IF strings are
  case-sensitive; wildcard patterns and numeric-picture switches remain cached.
- Deterministic bounded comparison of ordinary body-paragraph and simple table-row
  insertions/deletions, with genuine DOCX revision markup. A whole-paragraph decision
  consumes its mark and text together; removing the final tracked row removes its table.
- Opt-in final-column balancing for the documented ordinary-paragraph profile. Work is
  bounded to 16 probes across all sections plus one final layout, without shrinking
  text or increasing the final physical page allocation.
- Qualified Arabic/Hindi simple tables and paragraph headers/footers, plus separate
  managed chart/equation tagged/PDF-UA-1 and PDF/A-2b profiles. Required descriptions,
  language, logical ownership and combination limits remain explicit.

## Corrections and migration

Resolved-face line metrics replace fixed line-box ratios. Adjacent table rows no longer
have an artificial six-point gap, and indivisible row groups reserve their notes
together. Anchored wrapping is remeasured after moves; empty compatible continuous
sections no longer add a blank page. Header-note capacity avoids subtracting the header
height twice. These correctness changes can alter pagination relative to 1.3.x.
Review page counts and representative production documents when upgrading.

DOC and DOCX nested instructions cannot become truncated formulas or synthetic live
fields. Default BestEffort conversion retains its structural-mark omission behavior;
preserved unsupported story/nested revision owners fail explicitly. Structural comparison
serializes block signatures once per input, PDF reconstruction shares font metrics across
pages, and metrics-only import avoids parsing kerning/GPOS tables.

Public APIs are additive and validated against published 1.3.0. AssemblyVersion stays
1.0.0.0. All five core/OCR assets remain: `net462`, `net472`, `netstandard2.0`, `net8.0`
and `net10.0`. PDF input still requires the matching optional `wordnet.Ocr` package;
English OCR still requires local Tesseract and pinned language data. Actual Framework
4.7.2 x64 requires the documented legacy JIT configuration.

## Qualification and limits

The reviewed implementation has 1,139 required tests, including 28 review regressions.
Both local Linux x64 .NET 8/10 suites pass without skips; all-target builds, formatting,
packing and API compatibility checks pass. See the [review receipt](../roadmap-99-review.md)
and [original independent evidence](../roadmap-99-validation.md). Release qualification
must additionally pass on the exact final-main commit and its immutable packages:
Windows/Linux x64/ARM64 source/package/Standard lanes, actual Framework 4.7.2 source
and package guests, resource/performance gates, and independent output validation.
The publication workflow repeats the full native desktop package suites before pushing.

All 24 authored corpus checks pass, while all 24 independent reference comparisons retain
at least one failure at their original geometry/raster tolerances. The receipts preserve
these failures and unavailable references. No unrestricted rendering-parity or speed
superiority claim is made.

The [1.4.0 profile](../roadmap-99-implementation.md) defines admitted combinations.
STYLEREF remains a separate design stage. Complex structural revisions, complex
balancing, native/object combinations, combined archival/accessibility output, advanced
charts, additional OCR languages, encryption/signatures, and Android/macOS release
support remain outside the release. The unnumbered P3 proposal in #99 remains planning.

## Release evidence

Publish only the six immutable package/symbol archives from successful CI on the final
main commit. The stable release page must record that commit and run, archive hashes,
actual-runtime/cleanup reports, publication run and independent public-package verification.
Signed public archives can have different ZIP hashes; all original payload entries must
match the tested artifact. An isolated public-only consumer must restore matching 1.4.0
packages and exercise DOCX/PDF output on .NET 8 and .NET 10.
